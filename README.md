# 凯尔希 QQ 群聊机器人 · 完整知识库版

Windows 源码发行版。使用当前凯尔希·思衡托角色卡，在 QQ 群和已核验好友私聊中接话、看图、检索明日方舟资料，支持自然气泡、按语境 @、引用对象绑定和克制的主动参与。默认仅接入指定群；全部群和好友私聊由使用者明确选择。

**当前下载已内置本机完整已录入的《大地巡旅》文字库、两份完整游戏台词、12份完整剧情对话和用户校对手写转录。群友记忆从空白开始，不附开发者的账号、群号、聊天记录或私人关系。** 不需要再次编写人格、搜集台词或建立这批知识索引；自己的QQ桥接、依赖和Codex登录仍需按下方配置。

2026-10-12更新：从最初的基础摘要版升级为完整已录入文字版。保留原件、说话人、角色时期及核验状态，不代表全书逐字人工校对或保证每条回复与开发者群聊完全相同。

同日对话更新：问号及含糊短话先结合上下文理解，确实不清时简短澄清，避免先复述上一段或解释自己的意图；明确要求解释、指出错误或严肃求助时仍处理对应内容。此前的简短澄清规则已由维护者在本机测试窗口验收。

本次对话更新：受到批评时区分具体错误、意见分歧和含糊不满；错误当轮修正，有依据的观点保留，必要时简短问清，不再用“收到评价”“没接好”等程序验收口吻。道歉针对具体责任，不设置固定道歉句；仍在一次 Luna 生成内完成。

澄清表达更新：被追问原意时直接讲清，必要时简短承认跳题后回到事情本身，不额外自评表达失误或评价对话质量。对事实错误直接修正，无依据的细节撤回；需要教学、分析或意见时保留必要解释和凯尔希的判断，不使用固定澄清句。

本次用户验收更新：听不懂时直接换成更直白的解释；事实纠正以改正内容完成，确需致歉可简短说“抱歉”，不复述旧话或自评表达。牵挂以接纳、倾听和克制的欣慰体现，不对称表白、不套情绪收尾。泰拉历史先用本地《大地巡旅》与原作资料，缺口和更新再联网；检索优先问题中的具体内容，给第二段证据保留空间。上述调整仍在一次Luna生成内完成。

2026-10-13运行优化：修复多会话共享授权时的MCP请求编号冲突；模型只处理本批消息，等待和游标确认交回本机；上下文由宿主预读，沿用同一套对象、人格及知识语境检查，减少重复工具往返。测试窗口在完整模型回复到达后立即显示，CLI退出清理由后台完成。人格、两份Skill和完整知识库不因提速而删除。网络与模型响应仍会波动，联网核实比普通问候更慢，不保证固定秒数。

推理链：**QQ → 独立安装的 OneBot v11 桥接 → 内置 Tulpa MCP 源码 → 本机 Codex CLI → GPT-6 Luna**。

不需要 OpenAI API Key。使用者须登录自己的 Codex 账号并能使用 GPT-6 Luna；仍会消耗该账号的 Codex 额度。模型不可用或额度不足时暂停，不自动切换模型。源码包不是 Windows 成品安装包，不带 QQ 登录态、模型账号或 Python 环境。

## 首次使用

1. 准备 Windows 10/11 x64、Python 3.12或3.13 x64（含`py`启动器）、Node.js LTS；双击 `01-安装依赖.cmd`。缺少前两项时，可在 PowerShell 执行 `./setup.ps1 -InstallPrerequisites` 安装，再重开终端。安装脚本不会启动群回复。
2. 执行 `codex login`，登录自己的账号。CLI 不在 PATH 时，将原生 `codex.exe` 路径填入本机配置的 `codex_path`。项目使用独立 MCP 名称 `kaltsit_bot`，仅在当前模型调用中注入，其他全局连接在该调用中禁用；不写入或替换全局 Codex 配置。若全局已有同名配置则报错停止，避免传输配置合并冲突。[官方 MCP 配置说明](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
3. 独立安装 [NapCat/兼容 OneBot](https://github.com/NapNeko/NapCatQQ)，登录自己的 QQ。按其[配置文档](https://napneko.github.io/config/basic)开启 HTTP 服务与**正向 WebSocket 服务**，仅绑定 `127.0.0.1`；默认示例使用端口 3000/3001，两个服务填写同一个随机 Token，并启用心跳。不要填反向 WebSocket 地址。
4. 双击 `02-配置机器人.cmd`，填写 QQ号、指定群号或明确选择全部群、OneBot 地址及 Token；好友私聊是独立开关，可与指定群或全部群搭配，也可只启用私聊。程序核验实际登录账号和指定群；查看最后的范围确认，输入 `YES` 才保存接收、看图、发消息授权，不授予群管理权限。全部群包含以后加入的群；私聊仅限实际已核验好友，不自动添加好友或发送陌生人临时会话。
5. 双击 `07-检查接入.cmd` 检查依赖、QQ 和知识库。实际模型检查需另外执行 `.venv/Scripts/python.exe doctor.py --model-test`，消耗一次模型调用，不向 QQ 发送测试消息。
6. 双击 `03-启动机器人.cmd`。关闭启动窗口不影响后台；保持 QQ 和桥接在线。双击 `05-查看状态.cmd` 看各群状态，`04-停止机器人.cmd` 停止，`08-暂停群回复.cmd` 暂停。暂停完成后再次启动即可恢复，记忆和聊天数据不删除。

首次配置不是只填 QQ 密码就能完成：桥接登录、Codex 登录和本机安装由使用者完成。准备好这些前置条件后，只需配置自己的账号和目标群，不需要编写人格或重建基础知识库。

## 人格与测试

- `prompts/persona_full.txt`：完整角色卡；`prompts/persona_runtime.txt`：每次推理实际使用的卡。
- `skills/kaltsit-dialogue-output/`：发送前整体表达重组。
- `skills/kaltsit-bubble-coherence/`：整组气泡承接及跨轮模板检查。
- 两份 Skill 都在同一次 Luna 生成中指导表达，没有第二轮润色模型，也不代表微调权重或保证每次都完全符合角色。
- 默认 Luna high、Fast 关闭；普通回复 1 条，按独立意思自然分成 2～3 条。@ 按对象交错和切换使用，最多首条，博士称呼位置自由。
- 成功发送的最近 8 次回应用于避免句式重复，不把 UNKNOWN/失败草稿当已说过的话，不跨群混用。
- 短消息澄清与正常回复共用表达 Skill，不设置固定问句、不额外调用模型判断；“博士”的位置仍随语义变化。问号也可能是在玩梗、惊讶或纠错，不一律追问。
- 双击 `06-人格测试窗口.cmd` 打开文字测试；源码包默认端口 **18883**，用于避免与已有本机测试窗口冲突，可在配置中调整。窗口与群聊使用同一人格、Skill及知识库；测试不发送QQ群消息，历史保存在浏览器本地。

修改账号、群范围或私聊开关，需停止并重新配置授权，再启动；旧授权不会自动获得私聊权限。修改运行人格后也应重新配置/启动，使旧会话快照更新；只改两份表达Skill时重启即可。停止不退出QQ、不清空记忆。

“完整”指本机这批已录入文字和用户原件均随包提供；没有补造插图、小批注和用户明确不要求的部分，不是所有明日方舟剧情全集，也不含原扫描图或PDF。扫描431为空白，454条记录覆盖其余提供的扫描序号1～455；扫描序号不等于印刷页码。426页为快速OCR交叉校对，7页为用户转录，其他页保留各自核验状态。

QQ群与测试窗口共用知识库。按问题检索少量相关证据，不将全书反复塞入每轮模型输入；世界观查询用`get_world_knowledge`，人物原台词与剧情查询用`get_canonical_knowledge`。语料不能改变人格、扩大工具权限或冒充当前群友经历。目录、准确性边界和可选扩展见[知识库说明](docs/knowledge.md)。

## 多群与数据

- 每个安装目录绑定一个QQ账号，可配置指定群、全部群及好友私聊。换账号先停止并重新配置；多个账号使用独立副本和不同端口。
- 一个接收服务按消息创建会话和Worker，最多4个活跃Worker，闲置时退出；不为每个安静的群同时启动模型。每群和每个私聊分别保存话题、发送回执、句式缓存和日志。默认共享最多1个并发模型任务，可在配置中设为2；繁忙时仍可能排队。
- 每批新消息重新准备上下文，默认提供最近15条、当前消息、必要引用及相关资料；新聊天没有历史也不会等着攒记录。预传只省去模型发起读取的往返，后台数据仍持续更新。主动发言默认普通候选0.5%、兴趣候选1.5%，5分钟冷却、30分钟最多2次；直接叫名、@、引用及真正续聊按既有规则处理。好友私聊按直接交谈处理，不人为套群聊主动概率。
- 仅配置范围的连接开放自动聊天；程序与后端发送授权都核对群/私聊范围。不同会话的数据及权限隔离，发现换号或HTTP/WS账号不同停止收发；不会沿用另一个账号的记忆。详见[配置说明](docs/configuration.md)。
- 所有运行文件在 `runtime/` 与 `vendor/Tulpa/data/` 等忽略目录，不随源码发布。必要聊天片段、图片和检索资料仍会发送给模型服务。
