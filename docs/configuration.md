# 账号、聊天范围与升级

运行`02-配置机器人.cmd`完成真实OneBot账号核验，再确认授权范围。不要把凭据发到聊天或提交Git。

| 目标 | groups | all_groups | private_chats |
| --- | --- | --- | --- |
| 指定几个群 | 填实际群号字符串 | false | false |
| 指定群及好友私聊 | 填实际群号字符串 | false | true |
| 当前和以后加入的所有群 | 空数组 | true | false |
| 全部群及好友私聊 | 空数组 | true | true |
| 仅好友私聊 | 空数组 | false | true |

这张表仅说明字段，真正改变配置后必须停止、重新运行配置入口核验并授权。直接改JSON不能沿用不匹配的旧凭据。默认两个开关都关闭，群号列表由使用者输入；配置不接受从群消息修改范围或模型。

每个副本绑定自己的QQ账号、OneBot接口、Token、MCP端口与测试端口。OneBot HTTP和正向WebSocket必须来自同一账号，仅绑定本机。后台会持续核对账号；换号需要重新配置。所有群只指该账号实际加入的群，不自动批准入群邀请。私聊只接受已有好友，不自动加好友、回复陌生人临时会话或授权管理功能。

范围限制同时存在于本机消息分发、每个Worker的会话绑定和Tulpa后端发送检查中。开启私聊不会自动扩大指定群列表；旧版只允许群聊的授权不会自动获得私聊权限。

默认模型`gpt-6-luna`，reasoning为`high`，fast为false；模型不可用暂停，不换其他模型。`max_parallel_groups`默认1，可设2，表示所有群和私聊共享的最大并发模型任务，不增加每条消息的生成次数。测试窗口有独立串行锁；忙时不要连续点击发送。

数据保存在`runtime/group-群号/`和`runtime/direct-好友QQ号/`，上游会话保存在`vendor/Tulpa/data/`。知识库在`knowledge/`，与这些私人会话数据分开。常规使用不需要先导入QQ本地历史；每个新会话从空白记忆开始。

升级前停止旧副本，保留自己的私人配置和运行数据。更新代码后重新运行配置入口，不复制别人的账号或运行目录。检查`05-查看状态.cmd`，确认账号与接收通道，再试一个群或好友私聊。旧后台异常退出留下owner文件时，先确认对应副本已退出，再移除该副本的状态文件；不要按旧PID盲杀应用。
