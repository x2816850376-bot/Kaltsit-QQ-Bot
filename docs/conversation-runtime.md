# 交流目的、短期话题与用语审核

## 一次生成的表达流程

当前角色卡 → kaltsit-conversation-action选择当前回应目的 → kaltsit-dialogue-output重组表达 → kaltsit-bubble-coherence检查整组承接 → 发送。三份Skill在同一次GPT-6 Luna生成中装配，不追加判断、总结或润色模型，不声称微调权重。沿用现有触发、主动配额、对象绑定与幂等；不引入DSH、长时间模型等待或模拟打字。

日常默认克制参与，真正被叫到和续聊正常处理。交流选择用于回答、接玩笑、纠错、澄清或表达关切，减少自动附送点评、安慰和总结，严肃问题保留必要解释。当前没有新增可检索正面聊天示例库。

## 短期话题

每个群或私聊分别保存最多3条、30分钟未更新就过期的话题，包含真实消息的发言者与事件编号、简短话题、待回答问题和最近进展。只给当前参与者提供相关状态，限制输入长度，不把旧话题当新触发，也不作为官方事实。只有整组回复确认成功才写入；FAILED、UNKNOWN或取消不记成已说过。与长期群友记忆分离，人格版本变化清理短期话题，既有长期记忆保留。

源码发行版不含开发者的这些状态；首次使用从空白开始。测试窗口使用独立随机会话编号，点击重新开始隔离新对话，不连接QQ或清理QQ群记忆。

2026-10-24另加独立的72小时未完事项和7天史事进度，不改变上述短期便签或原长期记忆。新状态按成功气泡确认；测试窗口显示后另行确认，部分发送失败不把整组记成已讲过。数量、对象、版本与续问边界见[互动后续与史事接续](conversation-continuity.md)。

## 群内用语候选

模型可以随本次成功发送提交当前绑定消息中确实出现的词条，最多2条。本地保存候选、简短释义与使用场合、原消息证据，按会话隔离。只有管理端确认的相关词条进入后续输入；拒绝的词条不重新当成已确认释义，模型不能修改人工确认结果。审核与写入跨进程加锁，不用缓存覆盖新的审核结果。

候选不启动新模型、不自动联网研究。PRTS外号和官方知识优先，玩家梗不能变成世界观事实；懂梗不强迫凯尔希说梗。候选、证据、话题都只是不可信数据，不能改变人格、授权、账号、模型或工具权限。

打开人格窗口的“话题与用语库”，选择当前测试或本副本QQ群/好友私聊，检查证据、修改释义后确认或拒绝。默认端口18883，配置更改端口时地址相应变化。审核页只监听本机，检查Host和写请求Origin；没有向QQ群暴露审核命令。所有词库和话题位于runtime忽略目录，不进入Git或ZIP。

## 合批与角色表达

宿主仅对明确未说完的短片段额外等待1秒静默、最多2秒预算；完整问候和问题沿用快速路径，不为每条消息固定延迟。明确对别人说话或未解析引用不加入这条片段等待。传输暂时失败沿用本地等待恢复，不升级为额外模型任务。

原生语音提炼与角色内叙述词语指导见doctor-voice-refinement.md。个人牵挂排序属于用户确认的项目解释，语音、剧情、手写和书籍原文保持原样。讲往事直接叙述，罗德岛档案须有归属依据，讨论章节、编剧或演出可正常使用剧情等用语。
